# MCP tools

Generated by reading `mcp-npm/mcp-server-sdk.ts`: every `registerTool` call,
its input schema and the argument list its handler builds. A `tools/list`
request to the server built from this commit returns the same 16 tools with
the same parameters. When a tool changes, change this file in the same commit.

User-facing lists of the same tools: `mcp-npm/README.md` (section "All
Registered Tools", parameters per tool) and the root `README.md` (section
"Available MCP Tools", names with one line each).

## Rules shared by all tools that run `aid`

- The first argument is the path parameter as given; `aid` resolves a
  relative path against its working directory, `AID_ROOT` (SKILL.md section 5).
- The arguments are passed to `spawn` as a list, without a shell: a value
  such as `--include=*.go,*.py` reaches `aid` unchanged.
- An optional flag is added only when the parameter differs from the CLI
  default. "true -> `--x=1`" means the flag is added only for `true`;
  "false -> `--x=0`" only for an explicit `false`.
- Every input schema is a `z.strictObject`: a parameter name not in the
  schema fails the call with a `-32602` error that names it
  (`Unrecognized key: "include_privat"`), and the advertised JSON schema has
  `additionalProperties: false`.
- The run goes through the serial queue, the timeout and the output cap
  (SKILL.md section 5). A non-zero exit of `aid` is a tool error with aid's
  stderr.

The common filter parameters, where a tool has them:

| Parameter | Type | Argument |
|---|---|---|
| `output_format` | `text`, `md`, `jsonl`, `json-structured`, `xml` | `--format=<value>` |
| `include_private` | boolean | true -> `--private=1` |
| `include_protected` | boolean | true -> `--protected=1` |
| `include_internal` | boolean | true -> `--internal=1` |
| `include_implementation` | boolean | true -> `--implementation=1` |
| `include_comments` | boolean | true -> `--comments=1` |
| `include_fields` | boolean | false -> `--fields=0` |
| `include_methods` | boolean | false -> `--methods=0` |
| `include_patterns` | string, comma-separated globs | `--include=<value>` |
| `exclude_patterns` | string, comma-separated globs | `--exclude=<value>` |
| `expand` | string, comma-separated globs | `--expand=<value>` |

The analysis tools other than `aid_analyze` read `include_private` and
`include_implementation`, where they have them, differently: both default to
true there, and only an explicit `false` leaves the flags out;
`include_private` there adds `--private=1 --protected=1 --internal=1`.

## Distillation tools (`registerCoreTools`)

Fixed arguments: `--stdout --show-ai-agent-instructions`, so `aid` prints the
result and writes no file. An empty result is a tool error ("No output
received from aid command ...").

| Tool | Parameters (`*` required) | `aid` arguments |
|---|---|---|
| `distill_file` | `file_path`*, `output_format`, `include_private`, `include_protected`, `include_internal`, `include_implementation`, `include_comments`, `include_fields`, `include_methods`, `expand` | `<file_path> --stdout --show-ai-agent-instructions`, then the filter flags in the order of the table above |
| `distill_directory` | `directory_path`*, `recursive` (boolean, default true), the parameters of `distill_file`, `include_patterns`, `exclude_patterns` | `<directory_path> --stdout --show-ai-agent-instructions`, `--format`, `--recursive=0` when `recursive` is false, the visibility, content, include, exclude and expand flags |
| `distill_with_dependencies` | `file_path`*, `max_depth` (number, default 2), the parameters of `distill_file` | `<file_path> --dependency-aware --stdout --show-ai-agent-instructions --max-depth=<max_depth>` (`0` becomes `2`: the handler uses `max_depth \|\| 2`), then the filter flags; no include or exclude patterns |

`--dependency-aware` is experimental and regex-based; the tool's description
says so.

## Analysis tools

Each runs one `--ai-action`. None passes `--stdout`, so `aid` writes the
prompt or the task-list files where an AI action writes by default
(`.claude/skills/aid-architecture/SKILL.md` section 3) and prints a status
block. The tool text is built by `mcp-npm/tool-text.ts#aiActionText`: a line
of intro, `Output file: <absolute path>` (and `Task list: <absolute path>`
for a flow action) or "aid did not report an output file", a line of advice
when `aid` reported a file, then aid's own output. Relative paths that `aid`
reports are resolved against `AID_ROOT`.

## Tools that do not run `aid` (`registerMetaTools`)

| Tool | Parameters | What it returns |
|---|---|---|
| `list_files` | `path` (relative to `AID_ROOT`, default `AID_ROOT`), `pattern` (`*` and `?` globs matched against the whole path relative to `path`; `*` also matches `/`), `recursive` (default true) | compact JSON from `mcp-npm/list-files.ts#listFiles`: `path`, `file_count`, `total_size`, `languages`, and per file `path`, `size`, `modified`, `language`, `extension`. It skips subdirectories whose name starts with `.`, stops at `MAX_LIST_ENTRIES` (2000) with a notice first and last, and fails for a path that is not a directory. ## Calling a tool by hand

The package tests never run a tool against the real binary, so check a
changed tool like this, from the repository root:

```bash
export CGO_ENABLED=1 CGO_CFLAGS=-w
mkdir -p mcp-npm/bin && go build -o mcp-npm/bin/aid ./cmd/aid
(cd mcp-npm && npm ci && npm run build)
(printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"cli","version":"0"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"distill_file","arguments":{"file_path":"testdata/python/01_basic/source.py","include_private":true}}}'
 sleep 3) | AID_MCP_DEBUG=true node mcp-npm/mcp-server-wrapper.js
```

The first two commands put a fresh binary and a fresh build where the server
looks for them (both directories are ignored by git; in a checkout
postinstall downloads nothing). The server answers each request with one
JSON line on stdout; with `AID_MCP_DEBUG=true` it logs on stderr
`[AID MCP] Running command: <binary> [<arguments>]` for every tool that runs
`aid` (the `distill_*` tools also log `final args`). The `sleep` keeps stdin
open until the answer arrives; the server exits when stdin closes. Replace
the `tools/call` line with
`{"jsonrpc":"2.0","id":2,"method":"tools/list"}` to see every schema.
